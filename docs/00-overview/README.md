# 00-overview: 全体像

## 目的

- AIにテーマを与えて議論させ、その過程をWebで確認できるシステムを作る。
- 見る人の楽しみは、議論の勝ち負けではなく、議論の過程と、勝ち負けをどう判断したかを見ること。審判ごとの見方の違い(採点のばらつき)も見どころとして扱い、ばらつきをなくす方向には直さない。
- 開発の目的は、自身の学習兼遊びと、エンジニアとしてのポートフォリオ。
- 完成後、解説動画をYouTubeに公開する(→ `06-explainer-video`)。

## 領域間の関係

- ① 議論エンジン(`03-engine`)と ② 起動・表示(`04-app`)は、DynamoDBの発言データだけでつながる。
- 両者の取り決め(テーブル、起動入力)は `02-data-model` と `contract/` が正本。
- `contract/` を変えたら `02-data-model` を更新する。
- 人格定義(`05`)は `participants` から参照され、動画(`06`)はそのイラストを流用する。

## 開発の進め方

1. 共通の取り決め(テーブル設計、起動入力)を確定する。
2. ① 議論エンジンを作り、画面なしで議論が動くことを確認する。
3. ② 起動・表示を作る(ダミーの発言データで①と並行して着手可能)。

### リポジトリの公開

開発に使うリポジトリ(`tokyo-code-craft/ai-agorawl`)は非公開のまま使い続ける。公開用のリポジトリを別に作り、コードだけを写す。

| 項目 | 内容 | 状態 |
|---|---|---|
| 公開用のリポジトリ | `tokyo-code-craft/ai-agorawl-public`(公開) | 確定 |
| 履歴 | 開発の履歴は写さない。写すたびに「公開版(YYYY-MM-DD)」のコミットを1つ足す。作者とコミッターは、写す人の GitHub の noreply のアドレス(`<ID>+<ユーザー名>@users.noreply.github.com`)にする | 確定 |
| 写すとき | 区切りのよいとき(動画を出すときなど)に、開発に使うリポジトリの `main` から写す(`npm run publish-public`。→ `tools/README.md`) | 確定 |
| 写すもの | `main` でコミットしているファイルすべて(`CLAUDE.md` を含む)。ただし、PR の自動レビュー(`.github/workflows/claude-code-review.yml`)は写さない(公開用では PR を受け付けない) | 確定 |
| 写さないもの | Issue、PR、開発の経緯(#6)。文書の中の Issue の番号(「Issue #103」など)は、そのまま残す(公開用のリポジトリには、その Issue はない) | 確定 |

| README | 外の人向けに、何ができるか、動かし方(AWS のアカウントが要る)、費用の注意、Issue と PR の受け付けを書く | 確定 |
