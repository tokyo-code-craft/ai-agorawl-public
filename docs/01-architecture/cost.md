# 01-architecture: 費用の目安

モデルや検索の回数を決めるときの参考にする、費用の目安。仕様ではない。単価は、AWSの請求(Cost Explorer)の金額と使用量から逆算した値で、AWSの価格表の値ではない。価格が変わったら見直す。

調べた日: 2026-11-12(Issue #49)

## 議論1回あたりの費用

10ターン、審判3人、Web検索あり(`docs/03-engine/README.md`「動作確認用のモデルの組み合わせ」)。CloudWatchの Bedrock の指標(モデルごとの入力・出力のトークン数)を、議論の時間帯で合計した実測。

| 項目 | 使う量(1回あたり) | 費用(ドル) | 割合 |
|---|---|---|---|
| Web検索(Nova 2 Lite の Web Grounding) | 22〜27回 | 0.66〜0.81 | 約3分の2 |
| 討論者(Claude Haiku 4.5) | 入力 23万〜29万トークン、出力 1.4万〜1.8万トークン | 0.33〜0.42 | 約3分の1 |
| 検索の要約(Nova 2 Lite のトークン) | 入力 約0.9万、出力 約0.7万トークン | 約0.02 | わずか |
| 審判3人(gpt-oss-120b、Qwen3 235B、DeepSeek V3.2) | 各 入力 約1.6万、出力 0.05万〜0.3万トークン | 0.01〜0.03 | わずか |
| そのほか(Lambda、Step Functions、DynamoDB、API Gateway、CloudFrontなど) | | ほぼ0 | |
| **合計** | | **約1.0〜1.3(税抜き)** | |

- 審判は、2026-11-14 から Claude Opus 4.6 の3人に替えた(Issue #69)。上の表の審判の行は、替える前の測った値。Opus 4.6 の3人の費用は測っていない。入力・出力のトークン数が上の表と同じで、単価が入力 100万トークン 5ドル、出力 100万トークン 25ドルなら、3人で約0.5ドルの見込み(議論1回の合計は約1.5〜1.8ドル)。
- 31ターンの議論は、検索が1回あたり平均約60回に増え、発言の履歴も長くなるため、1回あたり2.5〜3.5ドルほど(Cost Explorerの合計からの概算)。
- 討論者の入力のトークンが多いのは、毎回のプロンプトに全発言と資料一覧を入れ、さらに1ターンの中で検索のたびにモデルを呼び直して同じ内容を送るため(→ `docs/03-engine/README.md`「Web検索と資料一覧」)。
- 費用は、ほぼ Bedrock(モデルとWeb検索)で決まる。ほかのサービスは、今の使い方ではほぼ0。

| 項目 | 単価(ドル) |

| Qwen3 235B、DeepSeek V3.2 | 調べた日には請求に出ていなかった(反映が遅れる)。使う量が少なく、議論1回あたり数セント以下 |

- 税(日本の消費税10%)が別にかかる。

## 月の見込み

| 使い方 | 月の費用(税込みの目安) |
|---|---|
| 10ターンを月30回 | 約35〜45ドル |
| 10ターンを月100回 | 約110〜140ドル |
| 31ターンを月30回 | 約80〜115ドル |

## 費用を左右するもの

- Web検索の回数(1ターンの上限、議論全体の回数)。一番効く。
- ターン数。検索の回数と、討論者の入力のトークン数の両方が増える。
- 討論者のモデルと、入力の送り方(プロンプトキャッシュを使うか)。
- 審判の人数とモデルは、今の使い方ではほとんど効かない。
