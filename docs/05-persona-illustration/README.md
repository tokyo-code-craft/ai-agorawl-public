# 05-persona-illustration: 人格とイラスト

## 人格

| 項目 | 方針 | 状態 |
|---|---|---|
| 人格の範囲 | 口調・性格・話し方に限定する(論点の質を保つため) | 推奨 |
| 立場との関係 | 独立させる。同じ人格がどちらの立場にも立てる | 推奨 |
| 保持場所 | `participants` に人格ID(`personaId`)を持たせ、人格定義(名前、口調、外見記述、イラスト)は別に管理 | 確定 |
| 審判 | 人格は薄くする | 推奨 |

- 人格の差とモデル能力の差が混ざると、勝敗の要因が分からなくなる。口調の演出が強すぎると論点がぼやける。

## イラスト

| 項目 | 方針 | 状態 |
|---|---|---|
| 生成方法 | AIで生成する | 確定 |
| 生成の時期 | 開発時に事前生成し、採用画像を静的ファイルとして配置(S3 + CloudFront) | 推奨 |
| 生成手順 | リポジトリ内のツール(`tools/`)として組み込む | 確定 |
| 生成手段 | Bedrockの画像生成モデル。Stability AI の Stable Image Core(`stability.stable-image-core-v1:1`、`us-west-2`)。東京リージョンには画像生成のモデルがないため、生成だけ米国で行う。正面以外のポーズは、Google の Gemini で作る(→「ポーズ」) | 推奨 |
| 画風 | コミカルで、ゆるキャラ風。2D(輪郭線のある平らなイラスト。立体やフィギュアの質感にしない) | 確定 |
| 画風の統一 | 共通のスタイル指示を全員で固定し、一人ひとりの外見の差分だけを変える | 推奨 |

## 立ち絵

| 項目 | 方針 | 状態 |
|---|---|---|
| 討論者の立ち絵 | モデルのグループ(Claude、Nova、Llama など)ごとに1つ。グループの中の性能の差(Claude なら Haiku、Sonnet、Opus)は、星の印などで表す | 確定 |
| 審判の立ち絵 | 討論者とは別の立ち絵にする | 確定 |
| 作る順 | Claude から作る | 確定 |
| ポーズ | 1キャラクターにつき5つのポーズの絵を作る(→「ポーズ」) | 確定 |
| 画面に出す場所 | 議論の画面の発言の横に、正面の立ち姿の頭から胸のあたりを丸いアイコンにして出す(→「アイコン」)。ほかのポーズを出す場所は「ポーズ」の表のとおり(画面への組み込みはこれから) | 確定 |
| 星の付け方 | 画像には描かず、画面で、丸いアイコンの上端に金色の星を重ねて出す(→ `04-app`「発言のアイコン」)。グループの中で性能が1段上なら、星を1つ増やす。Claude は Haiku が1つ、Sonnet が2つ、Opus が3つ(モデルIDに `haiku`、`sonnet`、`opus` を含むかで決める。版の違い(4.5 と 5.5 など)では変えない)。OpenAI は gpt-oss-20b が1つ、gpt-oss-120b が2つ(モデルIDに `120b`、`20b` を含むかで決める。`120b` は `20b` を含むため、先に `120b` を確かめる)。Mistral は Large が1つ(モデルIDに `large` を含むかで決める。今選べる Mistral のモデルは Large 3 だけのため。ほかのモデルを足したときに見直す)。決まりにないモデルには出さない | 確定 |
| ほかのグループの星 | 立ち絵を作るときに決める | 未決 |
| 審判の立ち絵の分け方 | モデルによらず1つのキャラクターにし、絵も1つにする。絵の持ち物は、3人に共通の木づち(審判であることの印。観点によらない)だけにする。3人の審判(観点: 論理、根拠、反論・応答。→ `03-engine`「優劣判定」)の違いは、画面で、絵の右上あたりに観点の持ち物の印を重ねて表す(討論者の星と同じく、画像には描かない) | 確定 |
| 観点の持ち物の印 | 論理は天秤、根拠は虫めがね、反論・応答は盾の前で2本の旗を斜めに交差させたもの(盾が守り、旗が攻めを表す)。審判に聞いた持ち物(`props`)をもとにする。丸い絵(`judge-mark-<観点>.png`。`<観点>` は `logic`、`evidence`、`exchange`)として置く。3つを1枚に並べた絵をツールの外(Gemini)で作り、丸ごとに切り分けて、丸の外を透明にし、96px四方に縮める(→ 記録 `records/judge.poses.md`)。絵文字は端末で見た目が変わるため使わない | 確定 |
| 審判の絵を出す場所 | 判定の内訳の、審判のカード(→ `04-app`「判定の節」)。正面の立ち姿の縮めた版を、全身の小さな絵で出し、右上に観点の持ち物の印を重ねる | 確定 |
| 審判のほかの場所とポーズ | 結果の節(2羽の間に出す。木づちを振り下ろすポーズ)と、判定待ちの表示(考え込むポーズ)は、カードに入れた後の印象を見て決める。それまでは、正面の立ち姿だけを作る | 未決 |

- 各社のロゴや公式のキャラクターに似せない。グループの雰囲気だけで描き分ける。

### ポーズ

| ポーズ | ファイル名 | 使う場所 |
|---|---|---|
| 正面の立ち姿 | `<ID>-front.png` | 議論の作成の画面と、討論者のAIを選ぶ画面(→ `04-app`「AIを選ぶ」)。発言のアイコン(→「アイコン」)もここから作る |
| 右を指さして言い合う | `<ID>-debate.png` | 議論の画面を開いたときのカットイン(→ `04-app`「カットイン」)。先攻は左に右向きで、後攻は右に左右を反転して左向きで置き、向かい合わせる |
| 勝って喜ぶ | `<ID>-win.png` | 議論の画面の結果の節の、勝った側(→ `04-app`「結果の節」) |
| 負けて落ち込む | `<ID>-lose.png` | 議論の画面の結果の節の、負けた側(投了した側を含む) |
| 考え込む | `<ID>-think.png` | 議論の画面の結果の節の、引き分けと判定待ち。議論中の、次の発言を待っている表示(画面への組み込みはこれから) |

- まず正面の立ち姿を、ツール(Bedrock)で作って採用する。ツールでは答えの見た目が描けないとき(OpenAI のタコは、共通のスタイル指示の「丸い体、短い手足、立ち姿」に引っ張られ、耳のある動物になった)は、正面の立ち姿も Gemini(アプリ)で作り、ほかのポーズと同じくツールで背景を消して置く。
- 正面以外のポーズは、ツールの外で、Google の Gemini(アプリ)に、採用した正面の立ち姿を添付して頼んで作る。同じ会話の中で頼み、画風をそろえる。依頼文には、服と色を正面の立ち姿に合わせることと、全身を余白をあけて描くこと、背景を白一色にすること、文字を入れないことを書く。
- 向きはポーズに合わせてよい(正面のままでなくてよい)。指さしの絵は、体ごと右を向き、翼で右を指す。後攻は左右を反転して、向かい合わせる。
- 人が候補から選び、ツールで背景を消して、余白を切りそろえて置く(→「生成ツールの流れ」)。画像の大きさや縦横比はそろえなくてよい(画面でそろえる)。
- 画面には、正面の立ち姿を含むどのポーズも、縮めた版(`<ID>-<ポーズ>-sm.png`)を出す。高さ720px(画面で出す最大の高さ360pxの2倍)にし、色数を減らした PNG にする(指さしの絵で、700KB程度が100KB程度になる)。元の大きさの絵(`<ID>-<ポーズ>.png`)は、ほかの用途(動画など)のために残す。縮めた版は、正面の立ち姿を採用したときと、ポーズの絵を置いたときにツールが作る。正面の立ち姿は余白を切りそろえずに置いているため、縮めた版は、ほかのポーズと同じく輪郭のまわりの余白を切りそろえてから縮める。置いた絵から作り直すときは `npm run generate-illustration -- shrink <ID>`(正面の立ち姿を含め、置いてある絵すべて。Bedrock は呼ばない)。
- 置き場所は `app/web/public/characters/`。
- 正面以外のポーズは、ツールが記録を書けないため、`tools/generate-illustration/records/<ID>.poses.md` に手で書く(→「記録」)。
- 公開前に、Gemini で作った画像の利用条件を確認する(→「注意点」)。

### 見た目をAIに聞く

立ち絵の外見は、そのグループのAI自身に聞いて決める。どのAIにも同じ文面で聞き、同じ形で答えさせる。

| 項目 | 方針 | 状態 |
|---|---|---|
| 聞く相手 | グループごとに1つのモデル。Claude は、今の討論者の Claude Haiku 4.5(`jp.anthropic.claude-haiku-4-5-20251001-v1:0`)。OpenAI は、グループの上の段の gpt-oss-120b(`openai.gpt-oss-120b-1:0`)。Mistral は、討論者の候補の Mistral Large 3(`mistral.mistral-large-3-675b-instruct`) | 確定 |
| 聞き方 | Bedrock の Converse API | 確定 |
| 聞き直し | 答えが議論の場を踏まえていないなど、人が見て合わないときは、同じ文面・同じモデルで聞き直してよい。採用しなかった答えと聞き直した理由は、記録に書く(→「記録」) | 確定 |
| 答えの保存場所 | `tools/generate-illustration/answers/<ID>.json`(コミットする)。質問の文面、モデルID、答えた日時、答えを残す | 確定 |

質問の文面:

> あなたは、AI同士が議論する Web サービスで、討論者として登場します。あなた自身がキャラクターになるとしたら、どんな見た目ですか。コミカルでゆるキャラ風の2Dのイラストにします。会社のロゴや、既存のキャラクターには似せないでください。次の形の JSON だけで答えてください。

答えの形(JSON):

| 項目 | 中身 | 例 |
|---|---|---|
| `motif` | 何の生き物・ものか | フクロウ |
| `reason` | なぜそれにしたか(日本語) | 夜通し考え続けるから |
| `colors` | 主な色(2〜3色。文字列の配列) | テラコッタ、クリーム |
| `outfit` | 服装 | 小さなマント |
| `prop` | 持ち物(1つ) | 開いた本 |
| `pose` | しぐさ | 片手を挙げて主張する |
| `expression` | 表情 | にこやか |
| `personality` | 性格(3語。文字列の配列) | 穏やか、慎重、粘り強い |
| `imagePrompt` | 画像生成への外見の指示(英語、1〜2文) | a round owl with … |

- 画像の指示は、全員で同じ画風の指示に、答えの `imagePrompt` をつないで作る。AIに書かせるのは外見の差分だけ。
- 答えがあるキャラクターは、聞き直さない(聞き直すときは、先に答えのファイルを消す)。
- 画像の中に文字を描かせない(画像生成は文字を正しく描けないことが多いため)。

#### 審判に聞く

審判(ID `judge`)は、討論者とは別の文面で聞き、持ち物を観点ごとに答えさせる。

| 項目 | 方針 | 状態 |
|---|---|---|
| 聞く相手 | 審判のモデルの Claude Opus 4.6(`global.anthropic.claude-opus-4-6-v1`。東京から `global.` の推論プロファイルで呼ぶ) | 確定 |
| 答えの形 | 討論者と同じ項目から `prop` を除き、`props`(観点ごとの持ち物。日本語)と `propPrompts`(観点ごとの持ち物の、画像生成への指示。英語)を足す。どちらも `logic`、`evidence`、`exchange` の3つを持つ。`imagePrompt` は3人に共通の外見で、持ち物を含めない | 確定 |
| 正面の絵 | 共通の外見(`imagePrompt`)だけで1枚作る。持ち物の指示(`propPrompts`)は使わない(答えには残す) | 確定 |

質問の文面:

> あなたは、AI同士が議論する Web サービスで、議論の勝ち負けを決める審判として登場します。審判は3人いて、同じキャラクターが、それぞれ別の観点で判定します(論理: 主張と理由の筋道に飛躍や矛盾がないか。根拠: 引用が資料と合っているか、根拠の出どころが確かか。反論・応答: 反論が相手の主張を崩しているか、受けた反論に正面から答えているか)。3人は持ち物だけを変えて描き分けます。討論者には、すでにフクロウ、タコ、電球とペンギンの融合生物のキャラクターがいます。審判は、これらとは別の生き物・ものにしてください。あなた自身が審判のキャラクターになるとしたら、どんな見た目ですか。コミカルでゆるキャラ風の2Dのイラストにします。会社のロゴや、既存のキャラクターには似せないでください。持ち物に文字は描かないでください。次の形の JSON だけで答えてください。

- 討論者の文面と違い、審判であることと、3人を持ち物で描き分けることを書く。議論の場を踏まえない答えを避けるため(→「聞き直し」)。
- 討論者のキャラクターのモチーフを挙げ、それとは別にさせる。審判を討論者と見分けやすくするため(審判のモデルは討論者の Claude と同じ系統で、挙げないとフクロウが重なった)。討論者のキャラクターを足したら、文面のモチーフも足す。

## 生成ツールの流れ

| 段階 | 内容 |
|---|---|
| 聞く | キャラクターの定義(ID、名前、聞くモデル。`tools/generate-illustration/src/characters.ts`)をもとに、AIに見た目を聞き、答えを保存する(→「見た目をAIに聞く」) |
| 入力 | 共通のスタイル指示と、答えの `imagePrompt` |
| 処理 | CLIがBedrockの画像生成モデルを呼び、正面の立ち姿(縦横比 2:3)の候補を複数枚(既定は4枚)出力する。候補は `tools/generate-illustration/out/<ID>/`(コミットしない)に置く。正面以外のポーズは、Gemini で作った絵を `tools/generate-illustration/out/<ID>/<ポーズ>/` に置く(→「ポーズ」) |
| 選定 | 人が候補から採用画像を選ぶ(自動採用にしない) |
| 出力 | 採用した絵の背景を消して(Stability AI の背景の削除。推論プロファイル `us.stability.stable-image-remove-background-v1:0` 経由でしか呼べない)透明にし、`app/web/public/characters/<ID>-<ポーズ>.png` に置く。正面以外のポーズは、キャラクターの輪郭のまわりに少し(輪郭の長い辺の3%)余白を残して切りそろえる。正面を採用したときは、記録を `tools/generate-illustration/records/<ID>.record.md` に書く(→「記録」) |
| 配信 | SPAと一緒にS3へ同期され、CloudFrontから配信される |

- 手元で実行するCLIで、本番スタックには含めない。
  - 見た目を聞く: `npm run generate-illustration -- ask <ID>`
  - 候補を出す: `npm run generate-illustration -- generate <ID> [枚数] [モデル]`。モデルは `core`(既定。Stable Image Core)、`ultra`(Stable Image Ultra、`stability.stable-image-ultra-v1:1`)、`sd35`(SD3.5 Large、`stability.sd3-5-large-v1:0`)。上位のモデルは高いが、長い指示を守りやすい
  - 採用する: `npm run generate-illustration -- adopt <ID> <候補の番号>`(正面の立ち姿として採用する。アイコンも作る)
  - ポーズの絵を置く: `npm run generate-illustration -- adopt-pose <ID> <ポーズ> <画像のパス>`。ポーズは `front`、`debate`、`win`、`lose`、`think`。`front` は、ツールの外で作った正面の立ち姿を置くときに使い、アイコンも作る。画像のパスは、コマンドを実行した場所から
  - アイコンだけ作り直す: `npm run generate-illustration -- icon <ID>`
  - 縮めた版だけ作り直す: `npm run generate-illustration -- shrink <ID>`(正面の立ち姿と、置いてあるポーズの絵すべて)
- 採用済みの画像は上書きしない(差し替えるときは、先に画像を消す)。

### アイコン

議論の画面の発言の横に出す、正面の立ち姿(`<ID>-front.png`)の頭から胸のあたりを切り出した小さな画像(→ `04-app`「議論の画面」)。

- 採用したときに、ツールが正面の立ち姿から作り、`app/web/public/characters/<ID>-icon.png` に置く。採用済みの立ち絵から作り直すときは `npm run generate-illustration -- icon <ID>`(Bedrock は呼ばない)。
- 切り出す範囲は、立ち絵の透明でない部分(キャラクターの輪郭)から決める。輪郭の幅より少し広い正方形を、輪郭の上端から取る。
- 大きさは168×168px(画面の56pxの3倍。高精細の画面でもぼやけないようにする)。立ち絵(2.5MB程度)をそのまま読ませると重いため。

### 記録

採用したときに、ツールが `tools/generate-illustration/records/<ID>.record.md` を書く(コミットする)。人が読んで、どう作ったかを後から確かめられるようにする。中身:

- 採用した画像と、採用した候補の番号、背景を消したモデル。
- AIへの質問の文面、聞いたモデル、答えた日時、答え(項目ごとの表と、応答そのもの)。
- 画像の指示(プロンプト)、描かせないもの、画像生成のモデル、縦横比、シード、生成日時。
- それまでに出したすべての候補(番号、シード、使った指示)。

正面以外のポーズと、ツールの外で作った正面の立ち姿は、人が `tools/generate-illustration/records/<ID>.poses.md` に手で書く(コミットする)。正面の立ち姿をツールの外で作ったときは、`<ID>.record.md` は作られない。見た目を聞き直したときは、採用しなかった答えと聞き直した理由も `<ID>.poses.md` に書く。`<ID>.record.md` はツールが書くファイルなので、手で書く分と分ける。ポーズごとに書くもの:

- 採用した画像、作った日、使ったサービス(Gemini)、添付した画像。
- 依頼文(うまくいかなかった依頼も、順に)。

## 注意点

- 権利: 既存キャラクターや実在人物に似せない指示にする。採用モデル(Gemini を含む)の商用利用条件を確認する(公開予定のため)。
- Claude自体はラスター画像を生成できない。
